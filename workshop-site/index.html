Launch Vibes

10:45 – 10:55 AM · ~10 min

Launch and Get Familiar with Agentforce Vibes

A fast, guided walkthrough before hands-on time begins: what Agentforce Vibes is, how to launch it, and the IDE areas you'll use for the rest of the session.

What you're building toward

Agentforce Vibes is Salesforce's enterprise-grade vibe coding environment, a context-aware, AI-powered IDE that turns natural language into working Salesforce applications. Built on the Salesforce Platform and Trust Layer, Vibes accelerates every stage of the development lifecycle: planning, building, testing, deploying, and iterating.

Unlike basic AI code assistants that generate snippets, Agentforce Vibes is designed specifically for secure, governed enterprise development. It understands your org's metadata, adheres to your patterns and Rules, and works with Salesforce tools such as Sandboxes, Code Analyzer, DevOps Center, and the Salesforce DX MCP server.

Why this mattersWhen you interact with Agentforce Vibes, you're collaborating with an autonomous coding partner that can analyze your project, create detailed plans, build metadata, generate Apex and Lightning Web Components, refactor existing code, resolve bugs, and deploy your app, all through natural language.

Step 1: Launch Agentforce Vibes

1.Open the Setup Menu and click Agentforce Vibes.

The gear/lightning icon in the top app bar opens the Setup Menu. Agentforce Vibes is listed below Your Account.

TipIt will take a few minutes for Agentforce Vibes to fully initialize. A Salesforce DX project will be automatically created for you and your org will be authorized by default.
2.If prompted with a "Do you trust the authors of the files in this folder?" dialog, select Yes, I trust the authors.

This appears the first time the IDE opens your new DX project folder.

TipYou may see a number of notifications in the bottom right of the IDE. This is where IDE or extension notifications are published. You can close any that appear on launch.
3.The Agentforce Sidebar should be open by default. If it isn't, select the Agentforce Vibes Icon in the sidebar to open it.

Look for this bear icon in the activity bar along the left edge of the IDE.

4.Select I agree to the terms and click Enable Agentforce.

The Agentforce Vibes panel, opened from the sidebar icon above.

Step 2: Get Familiar with the Agentforce Vibes IDE

1.Open the command palette (CMD+SHIFT+P on Mac or CTRL+SHIFT+P on PC). Use it to access Agentforce Vibes commands, SFDX commands, Lightning Preview, and project tools and utilities.
(Optional) Change your IDE theme by opening the command palette and searching for Color Theme.
2.Open the Explorer Sidebar to view your project files. Generated Apex classes, Lightning Web Components, and metadata will appear here.
3.Open the Org Browser Sidebar (cloud icon in the Activity Bar, or search Org Browser: Focus on Metadata View in the Command Palette). Use it to browse metadata in your org, expand objects, fields, Apex classes, and LWCs, and download metadata directly into your SFDX project.
TipDownloaded metadata gives Agentforce Vibes the context it needs for accurate planning and code generation.
4.Open the Extensions Sidebar to confirm the Salesforce Extension Pack is installed. This includes tools for SFDX commands, Org Browser, Lightning Preview, and MCP support.
5.Open the Integrated Terminal (CTRL+` on both Mac and Windows) to view output from SFDX commands, run optional CLI commands, and inspect logs or deployment messages.
6.Check the Status Bar at the bottom of the IDE. It shows your authorized org, active project, Lightning Preview activity, and MCP server status.
Watch forIf something appears to be "stuck," the Status Bar is usually where you'll see what the IDE is waiting on.

Summary

In this exercise, you launched Agentforce Vibes and activated it in your Salesforce org. You walked through the initial setup flow, enabled the agent, and confirmed that your development environment and sidebar were initialized correctly. With Vibes now running inside your IDE, you're ready to begin exploring the tools and features that support AI-assisted development.

Configure Your Agentforce Vibes Project

10:55 – 11:10 AM · ~15 min

Configure Your Agentforce Vibes Project

Connect Agentforce Vibes to your org's MCP servers, then explore what makes up a Salesforce project.

Step 1: Activate the MCP servers in Setup

1.From Setup, in the Quick Find box, enter MCP Servers, then select MCP Servers.
2.You will see the list of Salesforce Servers.
3.Open the salesforce-sobject-all MCP server and click Activate. Copy the server's URL; you'll need it in Step 2.
4.Open the salesforce-api-context MCP server and click Activate.
5.Open the Headless360 (H360) MCP Server and click Activate.

Step 2: Connect them in Agentforce Vibes

1.Open the Agentforce Vibes Sidebar, click the Toolkit tab, then click MCP Servers.
2.Toggle on salesforce-api-context and Headless360.
3.Click Add Server and paste the salesforce-sobject-all server URL you copied in Step 1 to manually add it.
4.Expand the Salesforce DX MCP server to see the tools it already has enabled.
TipSalesforce DX depends on your local CLI session, so it only works in local development. The three servers you just activated are hosted by your org, so they work no matter where you're running Vibes.

Step 3: Explore the makeup of a Salesforce project

1.Open the Org Browser Sidebar in Agentforce Vibes.

Look for this cloud/code icon in the activity bar to open the Org Browser Sidebar.

2.Expand Custom Objects and retrieve the Account object. Click the download/cloud icon next to it.

The cloud icon next to each object retrieves its metadata into your project.

3.Expand Lightning Component Bundle and download the genericPageHeader component.
4.Expand Permission Sets and download the Partner Management Permission Set.
5.Open the Explorer Sidebar and look through what you just retrieved:

The Explorer icon (top of the activity bar) opens this file tree. Folders with retrieved metadata appear in your DX project under force-app/main/default.

The Account object's fields and metadata
The Partner Management permission set
The genericPageHeader LWC, and how a component bundle is structured
Why this mattersThis is what a Salesforce project is made of: objects, components, and permission sets as files Agentforce Vibes can read, reason about, and generate against.

Step 4: Explore Skills, Rules, and Commands

1.In the Agentforce Vibes Sidebar's Toolkit tab, click on Skills, Rules, and Commands.
Skills are on-demand knowledge activated when a task matches the domain.
Rules are deterministic instructions applied always, or when files match a pattern.
Commands are reusable prompts injected inline when you type their slash trigger.

Summary

You connected Agentforce Vibes to your org's MCP servers, then explored the pieces that make up a Salesforce project: objects, components, and permission sets. Your environment is ready for the next step, where you'll use Vibes to build something new.

Hands-On Build, Part 1 – Option 1

11:10 AM – 12:00 PM · ~50 min

Hands-On Build, Part 1 – Option 1

Describe what you want, and build it with Agentforce Vibes.

What you're building

A Facility Inspection tracker: a simple object for logging site visits, safety checks, or compliance reviews. You'll describe it, add some sample data, ask a question about it, and document it, all in plain language.

Step 1: Build the object

1.Open the Agentforce Vibes chat and paste the prompt below.
Prompt
Create a custom object called Facility Inspection to track inspections of buildings and sites. It should have these fields: Site Name (text), Inspection Type (picklist: Health and Sanitation, Fire and Safety, Building Systems, Other), Scheduled Date (date), Inspector (text), Status (picklist: Scheduled, In Progress, Passed, Failed, Follow-Up Required), and Notes (long text area). Add it to a tab so I can see it in the app.
2.Review the plan Vibes proposes, then approve it.
3.Open the Salesforce org you're connected to. It may already be open in another tab; if not, click the monitor icon in the status bar at the bottom of the IDE.
4.Open the Facility Inspection tab to confirm it's there.

Step 2: Add sample data

1.Paste the prompt below.
Prompt
Generate 8 sample Facility Inspection records with a realistic mix of Inspection Types and Statuses. Include at least 3 records with a Status of Failed or Follow-Up Required, and spread the Scheduled Date values across the last 30 days. Use generic site names like "Building A" or "Main Street Site" rather than real addresses.
2.Approve the records, then open a few to check them.

Step 3: Ask a question

1.Paste the prompt below.
Prompt
Show me all Facility Inspection records where the Status is Failed or Follow-Up Required, sorted by Scheduled Date with the oldest first. Build this as a list view I can come back to.
2.Open the new list view from the Facility Inspection tab.

Step 4: Document it

1.Paste the prompt below.
Prompt
Write a short, plain-language summary of the Facility Inspection object, its fields, and the list view I just created. Write it so a coworker who wasn't in this session could understand what it's for and how to use it.
2.Read the summary Vibes writes back.

Summary

You built an object, added data, asked a question, and documented it, all by describing what you wanted. That's the whole loop: describe, review, approve.
